# status and inbox on indexes (T442)

`views.js` runs `status --json` and `inbox --json` through each CLI tree, one fresh process per run, on its own copy of one migrated state directory. The trees alternate run by run, so background load drifts over both alike. The dataset is a copy of the live state taken 2026-10-20 06:17 (Jerusalem): 446 tasks and 77,333 events (a 100 MB `events.jsonl`), prepared with `prepare.js --cli` and migrated to a 141 MB `state.db` by the T267 head (3c47f3c), the tree this task builds on. Each copy is the `.tower-crane` of a repository of its own, and commands run from that repository, as an orchestrator runs them.

Benchmark-only edit beyond `prepare.js --cli`: the copy's project records no repository, so `inbox` reads no GitHub. Its PR, CI and CodeQL reads are the network's time, the same in both trees.

Both trees print the same bytes: `inbox` is byte for byte the same, and `status` differs only in the host governor's live memory readings.

## Runs, 2026-10-20

Three runs of 30 per tree, after 2 warmup runs each, on the shared 24-core rig at load 18 to 33. Pooled over the 90 runs per tree:

| command | T267 p50 / p95 ms | T442 p50 / p95 ms | p50 | p95 | CPU ms/op, T267 to T442 |
|---|---|---|---|---|---|
| status | 1002 / 1159 | 195 / 226 | 5.1x | 5.1x | 1527 to 260 (5.9x) |
| inbox | 1014 / 1080 | 271 / 299 | 3.7x | 3.6x | 1479 to 333 (4.4x) |

Median of the three runs' p95 (min..max): `status` 1114 (1059..1210) to 226 (213..228), `inbox` 1074 (1055..1143) to 293 (286..316).

CPU is the command's and its children's, read from `/proc`. It moves least with load.

## Where the time goes now

Neither command reads the whole log. In `test/state-hot-paths.test.js`, with 3000 events of a cancelled task in the log, `status` and `inbox` read 2 event rows each and an observing `wait --inbox` 4; the T267 head's `status` reads 4005.

What is left in `status` (about 195 ms): Node start and module loading (about 50 ms), every task's evidence, notes and spend (one query, about 25 ms with parsing), the review history of the 133 tasks with a failed review (about 20 ms), the gate queue's working set (about 20 ms) and the gate reports of submitted tasks.

What is left in `inbox` (about 270 ms) is mostly fixed: Node start and module loading (about 55 ms), the `git rev-parse` that finds the repository for the worktree inventory (40 to 50 ms at this load), the 2451 unacknowledged orchestrator messages it lists (3.3 MB read, 4 MB printed), and the evidence of the 227 submitted and accepted tasks whose merge it checks. The orchestrator accepted `inbox` at about 4x on that breakdown (ruling, 2026-10-20). Module loading is T443's; the message backlog is T449's.

## Reproduce

```sh
node prepare.js --src <copy of the state directory> --out <datasets> --only live --cli
# Migrate the files with the older tree, so its copy has no indexes the newer tree adds.
TOWER_CRANE_STATE=<datasets>/live/files node <T267 tree>/bin/tower-crane.js project show
node views.js --state <datasets>/live/files --work <work> --tree t267=<T267 tree> --tree t442=<this tree> --runs 30 --out views-live-r1.json
```

The raw runs are `raw/views-live-r1.json` to `raw/views-live-r3.json`.
