- Worker spawn uses claim readiness for task status, dependencies, stack state, locks and worker slots, and refuses with the same reason before any worktree work or launch. Claim and spawn refresh existing stack membership from GitHub, while transient API errors remain retryable and do not disable stacks. A stack merges bottom up through the asynchronous merge API, pinning each PR to its accepted head with `expected_head_sha`, and an open PR whose head GitHub moved after a lower merge, the requested task included, takes the new head and needs its gates again. A stacked rework whose branch is gone resumes from its own pushed head, and a branch that already contains its dependency head is used as it is. A rework whose branch is recreated continues from the newest origin head that holds its submitted commit, so a stale tracking ref cannot restore an older head; a rework already claimed, which is in progress, keeps its submitted head the same way.
