- Fallback route pins in `owner/route-grants.json` key on the user file's canonical path, so a route the owner approved through one path runs when spawn reaches the same file through a symlink, another case on a case-insensitive filesystem or a relative `TOWER_CRANE_CONFIG`. A link moved to another file after the approval does not carry the pin. Pins written under the path as spelled still count for that spelling, and the next owner write for the file moves them under the canonical key. That write keeps the canonical entry, empty when no rung is pinned, so a cleared pin never comes back through an old spelling.
