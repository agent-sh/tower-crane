- No process outlives its gate. Each gate command's cgroup is killed and read back empty before the gate deletes its directory, on success, failure, timeout and interrupt. Windows gate commands run in a job object with kill-on-close. Without either, the gate stops the process group and its run-marked processes, and each command receipt records the backend as `cleanup`.
- At start and end each gate kills processes that name a deleted or finished gate or test directory, with their descendants, records a `gate reap` event and `status` shows `leaked processes killed`.
- Test wait loops have deadlines and end when their parent is gone. `npm run check:shared` rejects an unbounded wait or spin loop in `test/` and `lib/` unless the line gives a `// spin-allow:` reason.
