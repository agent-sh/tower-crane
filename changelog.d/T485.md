- Each project's Tower Crane scopes (agents, gates and merge-queue suites) run in a slice of their own below the caller's slice, at systemd's default weight, so one project's work never takes more CPU than another project or a terminal session. The slice is `agents-towercrane_<digest>.slice`, named by the same state directory digest as the task scratch.
- Inside that slice gate scopes get `CPUWeight=400` from the new `gates.cpu_weight`, four agents' shares, while agent scopes keep the default; `agents.cpu_weight` (default 100) sets theirs. Both are operational: `project set --gates-cpu-weight N|null` and `--agents-cpu-weight N|null`.
- Gate evidence and the merge queue's `head check` record the `cpu` weight their commands ran at, or why it was not applied (macOS, Windows, no user manager), and `status` prints `gate cpu weight:` for running gates.
- `scripts/measure-cpu-weight.js` measures the slices' fairness and a tests gate at two weights on a host.
