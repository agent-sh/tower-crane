- A stopped sandboxed agent no longer makes every other sandboxed agent's git calls wait 5 s. Its killed git shim could leave a marker in `.git/tower-crane-reap` that only a host cleanup judges. The supervisor now runs that cleanup, without waiting, as soon as its agent's process group ends.
- A marker from another pid namespace is judged by its holder: the namespace link, the innermost `NSpid` and the start time. Before, any live process in that namespace kept it, and namespace inodes are reused and outlive a shim killed alone.
- `SANDBOX_RUNTIME=1` and `CODEX_SANDBOX` mark a cleanup as inside a sandbox, as `TOWER_CRANE_SANDBOX=1` does. A marker with this boot id and another host name, such as one from a devcontainer on the same repository, is judged only from the initial pid namespace.
- Markers are synced before they are put in place. One that does not parse is gone once it predates this boot, and a prepared directory left without a marker is swept once it is older than the 5 s wait.
