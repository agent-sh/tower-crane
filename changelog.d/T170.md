- `check ci` judges each check name by its latest run at the submitted head, ordered by `started_at` and then `id`. A rerun or a reopened PR that succeeds now passes the gate; an older failed run of the same name no longer blocks it, and a completed, failed suite whose reported runs were all read and superseded by a newer suite is ignored; a suite still running, or with runs not all read, still blocks. A queued rerun has no `started_at` yet and is current when its `id` is above the latest started run's, so an older success no longer supersedes it: the gate waits for the rerun.
