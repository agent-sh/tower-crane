- A resumed agent keeps its state broker when the agent's previous monitor closes after the new spawn started, as it does while it still runs gates. That close used to delete the new `broker.json` and rename `brokers/<agent>/` to `.stale-<agent>-<id>`; codex binds that directory by path for each command, under the masked `brokers/`, so every fetch, push and submit of the resumed codex agent failed with `EACCES`, and a warm resume pointed at a deleted `broker.json`. Now a start and a close of one agent's broker directory take turns under `brokers/.<agent>.lock`, a start reuses the directory in place and writes `broker.json` whole by a rename, and a close removes the file, the directory, the socket and the socket leaf only while `broker.json` still holds its own token.
