- Spawn no longer fails when Windows briefly refuses to rename the freshly copied skill store into `skills/<key>/` (EPERM while a scanner or the indexer holds the new files). The rename is retried for up to 2 s, as state writes are. A store another dispatch published first counts as written at once, without the wait, and the temporary copy is removed.
- The same retry covers the rename that keeps a failed start's supervisor log, and the broker's move of an agent's pack into its push cache. A log whose rename is still refused after the wait stays under the agent's log name, and spawn reports the startup failure and that path instead of EPERM.
- A failed start records no spawn, so the next spawn reuses the agent's name and log name. A plain file left there, such as a log whose rename stayed refused, is now moved to a `-startup-failed-<time>.log` name before the spawn starts, instead of failing every later spawn of the task with `EEXIST: log already exists`. A link, a directory, a log that cannot be moved, or one a possibly running spawn of the agent wrote is still refused.
