- Automation stops replacing reviewers that crash at one head and revision after 3 crashes, so a reviewer that fails on its inputs is no longer redispatched in a loop. The third crash holds review dispatch with a `review held` event and `review_held` inbox item naming the count and the reviewer that ended last, how it ended and its log; `accept ID` dispatches the next one. Supervisor failures and monitors that die without an exit receipt count; outages, interrupts and budget stops do not.
- A stack link is refused only when what it read changed: the project settings and each chain member's status, head, branch, PR, stack record and merge state. Gate evidence, notes, usage and reviewer traffic during its GitHub calls no longer refuse it, so the link lands under a slow GitHub.
- A spawn monitor whose state directory is removed stops its agent and exits instead of letting the session run unrecorded.
