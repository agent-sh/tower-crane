- `hotfix ID --pr N --reason R` on a hotfix cancelled by a failure that was not the change's re-records it: the task returns to submitted at a new revision for `accept`, and its follow-up is cancelled with `superseded_by` and the reason. A claimed follow-up, or one with a branch, PR or commit, is refused. Dropping one with an owner ask, or one a failed independent review opened (`hotfix.rerecord_review`), is owner-required. `--reason` on any other record is refused. Follow-ups record the gate that opened them in `hotfix.follow_up_gate`, and the board says "re-recorded" and names the superseded follow-up.
- A hotfix tests failure whose every failing name also fails at the merge's first parent is infrastructure: the hotfix stays submitted and opens no follow-up. The base rerun for a hotfix uses that first parent (from `base_sha`, else the merge commit's first parent), since the newest main contains the merge. Such a failure fails on every rerun, so the owner can `accept ID --waive tests --reason R`, the one waiver a hotfix takes; it is recorded as `base_failure`.
