- `state.db` runs WAL with `synchronous=NORMAL`, SQLite's setting for WAL, instead of `FULL` (T255): a commit is in the log when its command returns and survives any crash of the process, and the log is synced at each checkpoint, so a write no longer waits on the disk. Only a power loss or an operating system crash can lose the commits since the last checkpoint, never part of one.
- A quality climb after a failed review dispatches the next rung again once the worker's monitor has recorded its exit. A process that kept its read history found the worker's spawn in one read of the log and its exit in another as different objects, so it waited for a cleanup receipt that was already there.
- Tests stop the followers and wait hosts they leave running before their fixture goes, so Windows can remove a `state.db` they held open; restoring a backup in a test closes the test's own connections first on Windows; the kill -9 durability test keeps killing until enough writes were acknowledged on a slow host; and the provider fallback tests no longer count the timer that closes a read's view as a wait.
