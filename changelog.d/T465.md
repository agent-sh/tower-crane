- Windows CI: the nested fork storm containment test gives its inner attempt a 4 GiB memory cap. The storm's thirteen Node processes measured 495 MiB of working set, close to the old 512 MiB cap, so the inner watchdog could stop the storm before the outer task cap saw it. The harness now prints an inner attempt's cap reason, and the Windows repeat job runs the test ten times.
- The retained lifecycle tests order their markers by signal. Fixture work writes its marker only once the test creates `go`, after awaiting the attempt's `containmentDone`, and a late-limit row writes it only after the keeper has stopped the work. The gate-owner row awaits the contained child `treeExec` launched, since on Windows `treeExec` returns before containment's stop of the leftovers ends. A loaded host took longer than the fixture's fixed 700 ms to stop an unrecorded supervisor-named child, which then wrote its marker and failed the test.
