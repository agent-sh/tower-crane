- A task sent back for conflicts on the same file past the threshold opens an orchestrator decision: land it in a merge pause, split it, or keep reworking. The decision blocks the task, so no worker or waiting owner reworks it until it is answered. The threshold is the project's 90th percentile of conflict reworks on one file, 3 until ten tasks have conflicted. Conflict reworks record their files as `conflicts`, and `status` lists `hot files`. JSON `conflict_hotspots`.
- A runaway `spend` flag opens one orchestrator decision for the task, with its spend, revision and main cause: conflict reworks, review rounds or gate failures. The decision blocks the task's next round.
- `merge pause ID --minutes N --reason R` holds other merges from the task's submit until it merges, goes back to rework or reaches the deadline. The task's reactions run first, ahead of the merges it holds. A `merge pause end` event records why the pause ended, and the held merges resume. `status` shows `merge pause:`, and held tasks wait `behind the merge pause`. JSON `merge_pause`. `--clear` lifts it.
