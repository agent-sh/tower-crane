- `wait`, `GET /api/messages`, the Claude Code event watch and the orchestrator's Stop hold hand out cursors that carry the length of `events.cuts.jsonl`. `wait` prints `cursor` (`OFFSET:CUTS`) beside every `offset` and takes it back with `--after`; the API returns `cuts` beside `cursor` and takes it back as `?cuts=`. Such a cursor resolves exactly across a lock recovery's cut, including the case a plain offset misses: a cursor from before the cut at an offset where a new line also ends. Plain offsets keep working as before.
- Recovery keys each cut record by the last event id of the commit it cut, so two cuts at the same place and of the same length are both recorded.
- Recovery writes a cut to `cut.<id>.json` before making it. When a tool through 0.1.2 finished a recovery that a newer holder left cut but unrecorded, the next holder records the cut as `late`; a reader goes back for it only when the bytes it last read were cut.
