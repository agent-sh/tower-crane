- `check ci` on a hotfix whose merge commit push run was cancelled by a newer main push, or never ran, accepts the first successful push, scheduled or manual run of the same workflows at a later main commit that contains it. The evidence names that commit and run in `hotfix_ci`. A failed run or job at the merge commit still fails.
- Hotfix CI no longer fails on a `ci.required` job that the main workflow skips by its own `if:` for the run's event, such as a pull-request-only job, or that also skipped at the merge commit. A job a path filter skipped on a later commit stays required.
- The later-commit scan reads every check run there, looks at up to five commits per check and records the commits it rejected in `hotfix_ci.rejected`, so the next check does not repeat them.
- The tests gate lists each changed host-only file's ran and skipped counts and skip reasons, and records them, redacted, as `skip_reasons` in the receipt. A hotfix whose changed host-only tests only skipped waits on `tests.host_env` as a `gate_config` inbox item instead of staying failed with no next step.
