- `check ci` on a hotfix whose merge commit push run was cancelled by a newer main push, or never ran, accepts the first successful push, scheduled or manual run of the same workflows at a later main commit that contains it. The evidence names that commit and run in `hotfix_ci`. A failed run or job at the merge commit still fails.
- Hotfix CI no longer fails on a `ci.required` job that the main workflow skips by its own condition, such as a pull-request-only job.
- The tests gate lists each changed host-only file's ran and skipped counts and skip reasons, and records `skip_reasons` in the receipt. A hotfix whose changed host-only tests only skipped waits on `tests.host_env` as a `gate_config` inbox item instead of staying failed with no next step.
