- `wait` and the board's SSE stream no longer replay restored history when a restore takes more than one read: `cp backup events.jsonl`, which truncates and then writes, or moving the log away and copying it back. Readers tell restored records by event id: a record they read since they started, or one from before a wait's start cursor up to the line that ended there, is history and stays queryable without waking. Any other record wakes, including one from a writer whose clock is behind and one that lands in the same read as the reset. Only an older backup without the start line falls back to records written no later than the reader's start.
