- Test fixtures no longer lose a concurrent change to a shared state file. The automation and inbox gh stubs, the supervision and fallback harness stubs and the Windows ancestry stub each read the whole file and wrote their own copy back, so a call that read before another call's write and wrote after it dropped that write. They now change the file under `updateJson` from `test/atomic-file.js`, which takes `missing`, the value a file not created yet starts from. `test/atomic-file.test.js` fails on a fixture that writes back a file it read, unless an `// update-json:` comment says why no other process writes it.
