- The orchestrator no longer runs its own waiter. In Claude Code the plugin ships a mod (`hooks/tower-crane.mjs`): the `watch` tool or `/tower-crane-watch` starts one `tower-crane wait --follow` child and every event becomes a prompt in the session. Orchestrators spawned on claude or codex get the same events from their home hooks, and their Stop holds until the next event while tasks are open. pi and OpenCode get them at tool boundaries; agy and command keep `tower-crane wait`. A push lists event ids only; `tower-crane event ID` prints the content. A default `wait` now skips bookkeeping (`hook progress`, `renew`, `spend` and the like; `--types all` keeps it), wakes on every owner event whoever it was addressed to, and on messages to the waiter's own name. `serve` adds an owner channel for board and phone clients: `GET`/`POST /api/messages`, content-free `wake` events on `/events`, and `msg --steer` for a message that should join the running turn; the orchestrator replies with `msg --to owner`.
