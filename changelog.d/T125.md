- Merge queue: an accepted PR GitHub already merged at its accepted head is confirmed through the merge gate without current gate evidence, so tasks accepted before merge evidence existed no longer block the line. A head the queue cannot advance is reported once in a `queue skipped` event and passed over, and the `merge queue` `done` event lists the skipped heads.
- Merge confirmation validates text and method before calling GitHub and records the lookup that proves the merge. Open PRs still require current passing gates, and gates that export only `run(ctx)` keep their existing checks.
- Each merge queue drain pass starts with a fresh skipped set, so a concurrent successful CI completion retries a skipped head before the executor exits.
- PR lookup refusals and unreadable GitHub responses skip the affected queue head instead of blocking ready tasks behind it. Later passes retry the head without repeating its skip event.
