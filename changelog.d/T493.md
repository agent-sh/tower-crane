- A long local CI run lands on a busy base. `merge` and the merge queue accept a local CI receipt behind the fetched base when the base still contains the checked commit, the head merges onto the tip cleanly, and the base changed no path the head changes or the command reads: a repository path its argv names (`.`, `./` and `./...` name the whole repository, and argv globs and `--flag=path` values count) or a new `ci.local.inputs` glob. Otherwise the queue reruns local CI as before.
- Each queue rerun records `local ci rerun` with the reruns in a row a base move left behind. After two, the queue holds new merges to that base for the task, and `merge ID` refuses other tasks' merges to it with the reason, until the task lands or leaves its accepted head.
