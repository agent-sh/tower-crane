- A sandboxed agent can fetch from an ssh or private https origin. Its `git fetch origin` goes through its state broker, which fetches with the user's login on the host and sends back the base, the stacked base and the task branch with a thin pack of what the agent lacks. The shim indexes the pack into the task repository and updates `origin/<branch>` and `FETCH_HEAD`. Before, fetch failed in the sandbox: no credential, no SSH agent behind the hidden `/run`, and ssh refused its own config files as "Bad owner" when root-owned files appeared owned by nobody. Only an origin that is the project's recorded GitHub repository goes through the broker, which refuses other branches; git fetches any other origin in the sandbox as before. A fetch whose pack cannot be indexed fails with index-pack's error. A fetch or push pack transfer ends after an hour, so a slow agent cannot hold the broker's cache lock. `git pull` from such an origin is refused with the fetch-then-merge way that works.
