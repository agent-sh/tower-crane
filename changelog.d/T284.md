- A personal fallback route that carries authority (`sandbox`, `env`, `env_file`, `scope`, a harness without an OS sandbox, the `command` harness, `web_mcp`, `mcp` or a non-built-in tool) runs only as `ladder set --fallbacks` wrote it under the authority check. That write pins a hash of each route, by position, covering those fields, the harness it resolves to and the `env_file` content, which the supervisor checks again when it reads the file, in `owner/route-grants.json` under the project's `owner_config_dir`, under a lock. Spawn skips a route that is not pinned, with a notice; `ladder show` lists it with the command that approves it. `ladder set --fallbacks` compares with the pinned routes, not the file. Routes that only name a model, profile, provider or effort on a sandboxed harness work as before.
- A sandboxed claude agent gets `CLAUDE_CODE_TMPDIR` apart from its commands' `TMPDIR`, so claude keeps its own temp files (prompts, plugin staging, task output) where its commands can read but not write them. It is in the agent's home, or beside the agent's temp directory when the home path would push claude's messaging socket past 103 bytes without `XDG_RUNTIME_DIR`. Before, they shared one directory, and a command could plant files that claude reads back.
- A brokered agent's git shim sets `GIT_CONFIG_NOSYSTEM=1` itself, so the remote URLs it checks and the git it runs skip the system config, as spawn's read of the remote hosts does.
