- Automation reruns a software gate whose passing evidence no longer matches its current inputs. A changed `gates.tests_cmd`, `gates.clean_cmd`, `gates.tests_proof_cmd` or tests mode used to leave the task waiting for a manual gate run, even though its recorded pass was for the old command. A failed gate still waits at unchanged inputs.
- `gates retry ID` (orchestrator or owner) reruns each failed software gate of a submitted task at its current head with the same inputs, for failures a later fix made obsolete, such as an infrastructure timeout. It refuses a task with no failed software gate and exits 1 while a retried gate still fails.
