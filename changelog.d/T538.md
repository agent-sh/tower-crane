- Merges go first. A head check now ranks by the accepted task it checks, not by the reaction that runs the merge line, which is often a merged task's. It takes the next free executor ahead of queued gate runs and keeps that turn while it waits for a full cap.
- The host governor reserves the CPU lines for one merge-queue suite while gate runs hold places. Past the load or CPU pressure line the suite is admitted and new gate runs wait. Memory lines still apply.
- `status` shows `merge waits: TASK since AT, behind WHAT` for each accepted task waiting to merge. JSON `merge_waits`.
- A head check deferred for a full executor cap or by the governor stays in `merge waits`. The merge queue records it as `blocked` with `deferred`, and `merge blocked` no longer counts it as a refusal.
