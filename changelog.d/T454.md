- `ci dispatch ID` runs the repository's CI workflow (`workflow_dispatch`) on the task's own branch at its head, so a worker gets the full test matrix without the orchestrator. Sandboxed workers dispatch through the state broker, for their own task only. The run is recorded in the task's `ci_dispatches`; a second dispatch at the same head is refused while the first runs, and `ci.dispatch.per_hour` (default 4) caps dispatches per task per hour. `project set --ci-dispatch` names the workflow and the limit.
- `ci checks` shows the latest dispatched run's jobs and, once it completes, each failing job's failing tests.
- The CI gate and submit set `workflow_dispatch` runs at the PR head aside. A skipped `checks (shared files)` job in a manual run no longer fails the gate, and the manual run's failures do not block the PR.
