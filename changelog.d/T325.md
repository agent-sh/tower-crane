- `gates retry ID --from-rework` undoes a rework that automation made for a failed `tests`, `clean` or `ci` gate once the cause outside the code is fixed, such as a gate temporary root on a full `/tmp`. The task returns to submitted at the revision it was submitted at, so that revision's passing evidence and any review count again, and only the failed gates run again. A gate that still fails reworks at a new revision. It refuses a rework from a review or a person, a revision or kind change since, a worker claim or submission since, a pending quality climb, and a moved PR or branch head.
- Automatic refill holds a restorable gate rework for `gates.rework_hold_min` minutes (default 5, 0 disables; `project set --rework-hold-min`), since the wait pass that reworks would otherwise dispatch a worker at once. `spawn --ready` by hand does not wait.
- An automatic gate rework records the failed `gate` on its `rework` event. The inbox `rework_ready` item shows `hold_until` and names the restore command only when it would succeed; otherwise `restore_blocked` says why.
- A reviewer stopped by that rework does not count as a held review or toward the reviewer exit cap after a restore.
- A restored revision number is retired: later revision bumps skip it, so evidence recorded at it never counts again. A wait host or CLI from before this version still bumps by one, so restart wait hosts after upgrading.
