- `gates retry ID --from-rework` undoes a rework that automation made for a failed `tests`, `clean` or `ci` gate once the cause outside the code is fixed, such as a gate temporary root on a full `/tmp`. The task returns to submitted at the revision it was submitted at, so that revision's passing evidence and any review count again, and only the failed gates run again. A gate that still fails reworks at a new revision. It refuses a rework from a review or a person, a revision change since, a worker claim or submission since, a pending quality climb, and a moved PR or branch head.
- An automatic gate rework records the failed `gate` on its `rework` event, and the inbox `rework_ready` item names the restore command when it applies.
- A restored revision number is retired: later revision bumps skip it, so evidence recorded at it never counts again.
