- The event log append is synced before a command returns, so an acknowledged message, hook delivery or mutation survives a power loss.
- A commit logs its events before the files they describe. Changed files are staged and synced as `<name>.json.<event id>.commit`, the events are appended and synced, then the files are renamed into place. The next lock holder finishes or discards a commit whose writer died, so a crash never leaves a task change without its event.
- Atomic writes sync the directory after the rename, except on Windows, which cannot sync a directory.
- tasks.json records `last_event`. `validate` reads under the lock and also reports a tasks.json change whose event the log lacks.
