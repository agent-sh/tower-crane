- Gates, merges and broker commands a dispatch supervisor runs keep the host environment. The supervisor starts with the dispatcher's environment; the agent's home, shim `PATH`, task cache, `TOWER_CRANE_SANDBOX`, identity and credentials apply only to the harness process. A gate triggered after an agent exits no longer runs under that agent's `HOME`, so git there never reads a `~/.gitconfig` the agent wrote, and its tests see no agent variables. A brokered `ci log`, `ci checks` or `ci alerts` runs the host `gh` instead of the agent's gh shim, which refuses `gh api`. When the project sets `gates.tmp_root`, those gates run under it instead of the dispatcher's `TOWER_CRANE_TMP`.
