- `wait` and `wait --follow` no longer drop an event after recovery cuts a crashed commit's lines they had read and the next commit appends as many bytes. Before, the log kept its size and inode, so the wait never read the new line; a smaller append was read from the old position, mid-line. A wait now compares the last line it read on every read, and when the same file was cut it hands on the events after the last one the log still holds. A replaced log is still not replayed.
- The lock-free read fast path now checks the filesystem on macOS and Windows too. On macOS it runs only on APFS and HFS+, by the type `mount` lists (statfs `f_fstypename`); SMB, NFS, AFP, WebDAV and FUSE mounts always compare the last line. On Windows a state directory on a UNC share, or a mapped drive that resolves to one, always compares. Other platforms always compare.
