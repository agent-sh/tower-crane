- A failing tests command reruns its failing files once in the same checkout, and a failing local CI command reruns once on the same merge, before any rework. A rerun that passes passes the gate and records each test as `flaky` with both runs' receipts; a new failure that persists on rerun reworks as before. Each command reruns at most once, and nothing is guessed from the diff. Only a command that is `gates.tests_proof_cmd` over a known file list reruns just its failing files; any other command, such as a full `tests_cmd` that may stop at its first failing part, reruns whole, as does a first run whose output was cut to its kept tail. A rescued command's summary line gives its first exit beside the rerun's, and a failed rerun names the tests that failed on it. Local CI reruns only the failed steps its receipts name through the new `ci.local.rerun_cmd` with `{steps}`, else the whole command (`rerun_cmd` is for a checker that goes on after a failed step or lists the steps it skipped); `ci.local.rerun: false` turns the rerun off.
- A merged tree that moved during local CI is no longer a failure: the gate runs again on the new merge, and a base that keeps moving leaves a pass that automation reruns, never a rework.
- A test flaky in two different tasks within 7 days opens one `Fix flaky test` task with both runs' commits and log excerpts in its brief, once per test, counted by event order after its last flake task.
- Tests receipts list each rerun in `receipt.reruns`. The native crash rerun is one case of the general rerun; only a reverted run still needs every failure to be a crash.
