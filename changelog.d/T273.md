- A sandboxed claude reviewer or small agent hides the whole user's home, like a worker. It used to hide only the entries beside its read-only worktree's path as they were at spawn, so a file or directory made in the home later, such as a new credential file, was readable to its commands. Its `denyWrite` now lists each protected dotfile the worktree lacks before the worktree, so claude binds those placeholders while the worktree is still writable inside the hidden home. On a real home the profile shrank from 2,085 `denyRead` entries (120 KB) to 7 (9.5 KB).
- `test/live-sandbox.test.js` has a real claude and codex small agent read files the test makes in the home after the agent's command starts.
- The live codex probes in `test/secret-canary.test.js` and `test/sandbox-extensions.test.js` keep their scripts in the project's writable directory and name their read-only toolchain with `sandbox.read`, since codex mounts nothing beside the home but named paths. The canary holder's command passes `{prompt}`, which the command harness requires.
- A sandboxed claude or codex agent reads only the code of the Tower Crane checkout it runs from (`bin`, `lib`, `agents`, `skills`, `standards`, `package.json`, a pinned `tool.json`), and the same of `TOWER_CRANE_PLUGIN_ROOT`. It used to read the whole checkout, so an agent of another project could read that checkout's own `.tower-crane/brokers/*/broker.json` tokens and `.tower-crane/homes/`.
- After a claude agent exits, its monitor also removes the empty placeholder directories, `.claude/.cc-writes` and `.claude` it made. A claude spawn first sweeps placeholders an earlier agent left behind: empty, read-only, single-link files and empty directories by those names that git does not track. `submit` refuses a head whose commits add an empty file by one of those names.
