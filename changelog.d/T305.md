- A git shim killed while it cleaned up placeholders no longer stalls every later git call in the repository. Stopping an agent kills its process group, and a shim there could hold `.git/tower-crane-reap`. The directory stayed, so every later cleanup waited 5 s and kept its placeholders. A supervisor runs three git calls through the agent's shims before it reports its start, so every later spawn missed its 10 s startup window with "supervisor startup failed". The directory now holds a marker naming its holder, and a cleanup removes the marker of a holder that is gone and takes the directory. A live holder, even paused, still keeps it. A shim killed inside an agent's command sandbox runs in a pid namespace of its own; a cleanup on the host removes its marker once that namespace has no process left. Where there is no readable `/proc`, as on Windows and macOS, cleanups no longer take the directory, since they could not remove a placeholder anyway.
