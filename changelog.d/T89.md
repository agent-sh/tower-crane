- Two control modes over one authority table. Every allowed change of a guarded setting appends one `setting` audit event naming the command, actor (owner or orchestrator), mode (board or cli) and each setting's class. Escalations offer `approve` and `decline`; after the owner approves, on the board or with `answer`, the orchestrator's identical request applies the approval once (`applied` on the decision, `approved_by` on the audit event and on an approved waiver). A waiver is audited only by the accept that records it, and an approved waiver counts only for the task and commit its escalation named. `ask --setting S` requests an owner-required change no command makes, such as `publish`; a setting some command changes is asked for by running that command. An orchestrator spawn uses the owner's delegation approval, and audits it, only once the spawn has started. `tower-crane authority` lists every row with its class and command. Board controls for the remaining settings follow separately.
