- Spend records price Bedrock and 1M-context Claude ids using an exact configured row first, then their canonical model as a fallback: `global.anthropic.claude-X`, `anthropic.claude-X` and `claude-X[1m]` use the `claude-X` fallback row. Bedrock `-v<N>:<M>` suffixes are dropped too: `global.anthropic.claude-haiku-4-5-20251001-v1:0` matches `claude-haiku-4-5-20251001`; release dates remain distinct. A run on several models records its primary model with each model's own counts, instead of one comma-joined id. Spend entries record `billing` (`api`, `subscription`, or `null` when unknown or local), and `bench tokens` reports metered USD beside the list-price equivalent. Provider, context and version rows retain their own rates, and base-valid schema-1 price tables keep loading and saving. A resumed Claude run subtracts its baseline from each model's own counts, so earlier models are not priced again. A Claude rung that names no provider bills as `api` when its environment or the user's settings file turns on any Claude Code provider switch (Bedrock, Vertex, Foundry, Anthropic on AWS or Google Cloud, Mantle, gateway). A user `apiKeyHelper` bills as `api` too. A pinned Claude provider now turns all of those switches off for the agent, so an inherited one cannot take the route. Codex billing follows the configured `model_provider`, including standalone profiles, legacy profile tables and supported `-c` overrides, so Bedrock runs count as `api` even when credentials are loaded from `CODEX_HOME/.env`. Missing or unreadable selected routes are unknown (`null`), not subscription, and local Codex providers (`ollama`, `lmstudio`, `oss`) are `null` too. `bench tokens` lists a historical record with a joined model id as `legacy joined: <id> + <id>`.
