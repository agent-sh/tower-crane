- The host governor no longer defers work on load alone where Tower Crane's gates and agents run under CPU weights. There CPU pressure decides: CPU `some` avg10 at 60% defers, and load defers only once it saturates the host at `load_saturated` (default 2) times the cores. Over the week to 2026-10-24 the old load line deferred 788 tests-gate starts while CPU stall stayed under 24%; a weighted burn of one core count of extra work left the desktop's own CPU stall unchanged.
- Without CPU weights (no systemd scopes, or no `cpu` controller), or without a CPU pressure reading, load still defers at `load_defer` times the cores. The merge-queue suite's share passes the pressure and `load_defer` lines, not the saturated one.
- A gate or agent launched without a systemd scope now runs under `nice` and, on Linux, `ionice -c2 -n7`: agents at nice 10 and gates lower by their weight over the agents' (nice 4 at the default 400). Receipts and `status` show it beside the weight that was not applied.
- `status` names the CPU rule in force and which signal defers work (`host governor defers work on cpu pressure: ...`); reasons start with `memory`, `memory pressure`, `cpu pressure`, `saturated load` or `load`, and JSON `governor.signals`, `governor.reading.weights` and each deferral's `signals` carry the same.
