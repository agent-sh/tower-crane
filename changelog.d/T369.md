- Security: only an explicit owner's `init` at a terminal records the user file's folder as `owner_config_dir`. Any other `init`, the orchestrator's included, records the default `~/.config/tower-crane` under the account's home directory, and a headless owner `init` checks the owner key there. `TOWER_CRANE_CONFIG` and a key planted beside it no longer let a non-owner choose where the owner key and the owner's records live. An account whose home is missing or `/` is refused instead of recorded.
- Tests bind the default owner directory inside each fixture through a test-only preload, and fixture cleanup fails a test whose project points outside the fixture.
- Security: an `init` by anyone but the owner no longer copies owner-required parts of the user file's primary rungs into `project.json`. It leaves out `sandbox`, `env`, `env_file`, `scope`, `command`, `web_mcp`, sandbox-changing tools and undefined MCP servers, and writes the built-in rung for a rung that would run as a command or outside its sandbox. Each is named in a `notice:` line and in the `init` event's `withheld`.
