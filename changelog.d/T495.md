- `gates.final_review` (`project set --final-review JSON`) names an external reviewer, such as `revuto review {repo} {pr} --final`, that `accept` asks once per head and revision after every other gate passed. With `"when": "capped"` it runs only when a check run at the head matches `capped_pattern`, the reviewer's round-limit message. It runs from a gate worktree at the commit with the gate environment and expands `{repo}`, `{pr}` and `{sha}`. Exit 0 accepts; `concerns_exit` (default 2) sends the task to rework with the command's output and the PR's review comments at the head; any other end is recorded as `refused` or `not_run` and does not block. A run that `wait` shutdown interrupted is no verdict: the task stays submitted and the next `accept` asks again.
- `final-review` evidence carries the command receipt and its outcome. The `accept` event and output, `status` (`final review: T1 refused at abc1234`, JSON `final_reviews`) and the board show it.
