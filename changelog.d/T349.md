- Hotfix `check ci` no longer confirms a failure at the merge commit that the base already had. When every failed job there failed the same way in an earlier run of the workflow on the base (the same failing test names, or the same job name when its log names none), among the last 30 completed runs at commits the merge commit contains, the failure is `main_red`: CI waits for a later green run that contains the merge commit, as it does for a cancelled run. A failure new at the merge commit stays confirmed. The evidence records `hotfix_ci.failure` with the classification, the parent run and, per failed job, the earlier run that failed it.
