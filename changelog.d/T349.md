- Hotfix `check ci` no longer confirms a failure at the merge commit that the base already had. A failure is `main_red` when each failing test of each failed job also failed in an earlier run of the workflow on the base, at a commit the merge commit contains and among the last 30 completed runs of the past 7 days, in the same job once the shard is set aside and with the same first error line. CI then waits for a later green run that contains the merge commit, as it does for a cancelled run. A test in the hotfix's diff counts only at the parent run. A test failing with a generic error, such as a timeout or a wait for a path, also counts only at the parent run. A job that names no failing test counts only for a proof, probe, check or lint job that failed at the parent run with the same error line from its failing step, and a timed out or cancelled job never counts. Any other failure stays confirmed.
- Hotfix CI evidence records `hotfix_ci.failure`: the classification, the parent run and, per failing test, the earlier run, job and error line that matched it. A recheck of the same run attempts reuses it without reading logs.
