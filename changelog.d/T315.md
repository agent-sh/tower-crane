- The `process.kill` lint in `npm run check:shared` exempts only the interposer line in the named fixtures: `const kill = process.kill;` directly followed by `process.kill = function (pid, signal)`. In those files `process['kill'](0)` and any use of the held alias other than forwarding the replacement's own, unchanged pid and signal are now rejected. Before, a named fixture was exempt from every alias check.
- The lint now rejects optional-chaining calls such as `process?.kill(0)` and `process.kill?.(0)`, `process[name]`, `const { kill } = globalThis.process`, `p.kill` after `const p = process`, and `global.process.kill(pid)`, `globalThis?.process.kill(0)` and `f(...process.kill(pid))`. It no longer flags comparisons (`process.kill === original`, `assert.equal(process.kill, original)`), quoted sentences (`'do not call process.kill(0)'`) or `child.process.kill(pid)`.
- A test pins the second `wait` signal during the tests gate's base rerun: the failure records `base_rerun_killed` with signal `SIGKILL`, and the next `wait` retries the gate once at the same head.
