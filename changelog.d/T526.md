- A sandboxed codex agent's commands no longer get credential-shaped variables. The agent's `config.toml` sets a `shell_environment_policy` that keeps out every `AWS_*` name, every name holding `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD`, `PASSPHRASE` or `CREDENTIAL`, and every name the user's codex `.env` sets. codex itself still gets them. git's `GIT_CONFIG_KEY_<n>` entries and Tower Crane's own variables still reach the commands. A credential-shaped name in `env` or `env_file` now reaches codex but not its commands.
- A sandboxed claude agent's commands no longer see the host's `/tmp` on Linux, where the X11 and session bus sockets live. The sandbox allows back only the paths the agent needs there. `/tmp` stays visible when the agent keeps a caller's `TMPDIR` of `/tmp`, where claude makes its proxy sockets.
- A sandboxed claude agent's commands still get the credentials in claude's environment, apart from GitHub's. `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` is not set: in Claude Code 2.1.305 it also turns off the edit mode agents rely on and writes stub files into the worktree. `docs/state.md` has the details.
