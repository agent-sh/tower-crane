- A sandboxed codex agent's commands no longer get any name that holds `KEY`, `FOO_KEY_1X`, `API_KEY_1` and `OPENAI_KEY_2` included, and claude denies those names to its commands too. Tower Crane now sets git's command-scope config in `GIT_CONFIG_PARAMETERS` instead of `GIT_CONFIG_COUNT` with `GIT_CONFIG_KEY_<n>`: the harness's own entries, the claude placeholders' `core.excludesFile` and the CLI's own git. A spawn moves the dispatcher's `GIT_CONFIG_COUNT` entries there too, so a sandboxed harness starts with no `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>` or `GIT_CONFIG_VALUE_<n>`, and codex keeps all three from its commands. Inside the sandbox, the git shim still drops the harness's entries but `gc.auto` and `maintenance.auto`. claude's sandbox replaces each command's `GIT_CONFIG_PARAMETERS` with its own proxy entries, so the agent's global git config file now also sets `gc.auto=0`, `maintenance.auto=false` and, for claude, the placeholders' `core.excludesFile`; in claude's commands these are global scope, and the repository's own config wins over them.
- A sandboxed claude agent's commands never see `/tmp` on Linux. Its read grants never hold `/`, `/tmp`, or a directory that holds `/tmp` or the user's home. A PATH directory, PATH install prefix or kept caller `TMPDIR` that holds the state directory is not granted either. Spawn prints a notice for each one it drops and never widens one to its parent. A PATH directory whose prefix is dropped is allowed back alone. Before, `/tmp` on PATH granted `/`, and a kept caller `TMPDIR` of `/tmp` left `/tmp` visible. With a caller `TMPDIR` of `/tmp`, claude's proxy sockets there are out of reach, so https from commands fails, as it does for a `TMPDIR` under the home; a shorter cache root (`XDG_CACHE_HOME`) gives the agent a temp directory of its own.
