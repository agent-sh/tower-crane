- Worker merges and checkouts through the git shim no longer fail when they bring in a path Claude's sandbox masks, such as a tracked `.mcp.json` or `.claude/settings.json`. The Git shim and placeholder cleanup share the complete classified mount list, including `.claude/skills`, hooks, output-styles, routines and workflows. Every root name on that list counts as mounted whether or not it exists at spawn, since Claude mounts it either way: a read-only bind of what is there, `/dev/null` over an absent name, or an empty read-only `.claude` when `.claude` is absent. A path inside any read-only directory is held off the worktree too. Inside claude's sandbox the shim builds the move with plumbing and leaves the masked file as the sandbox gave it. Protected names match case-insensitively through the default three-component search depth, including `lib/.Bashrc` and `web/.VSCode/settings.json`; a read-only protected directory covers its subtree. Newly added nested paths below the root, with no existing mask or read-only ancestor, reach the worktree normally. A test runs every mount name, file or directory, present or absent at spawn, through a merge and a checkout that add, change and delete a tracked path under it, inside real bubblewrap mounts built as Claude builds them. A merge needs git 2.38 or newer. A checkout covers a branch or a revision, with `--detach`, `-b` or `-B`. A move that conflicts, has staged changes, or uses an option it does not honour is refused with the reason. A checkout of a branch another worktree has checked out, or of a name git rejects, is refused before anything moves. A branch named by `@{-1}` is the previous branch, as in git, and a name that is both a branch and a tag checks out the branch. The move's reflog entries read as git's do.
