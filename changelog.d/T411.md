- An open decision closes itself as moot in the write that closes the last task it waits on: every task it blocks, and the task an approval request would change, is accepted, cancelled or superseded. It records `withdrawn_by: "engine"`, `moot: true` and a reason naming each task, in a `decision withdraw` event. Before, only its asker or the owner could withdraw it.
- A worker's or reviewer's question that blocks a task whose latest tests failure also fails on main goes to the orchestrator as a technical decision with `routed`, whatever kind it was given, unless it is `spend` or `crisis` or names an owner-required setting other than a gate waiver. `ask --kind credential` now needs a `--setting` that grants a credential or loosens a sandbox; a failing host or harness is technical.
- `needs_owner_by` records who set a task's `needs_owner`. Cancelling past a hold the orchestrator or the engine set is the new operational `task.cancel_hold`; a hold the owner or a worker set stays `task.cancel_needs_owner`, owner-required.
- `project set --publish-policy '{"conditions": [...]}'` sets a standing publish policy once (`publish.policy`, owner-required), with the conditions `review_clean`, `full_suite` and `main_ci_green`. While they hold for an accepted release task, the orchestrator's `ask --setting publish --change '{"task":"T<n>"}'` exits 0 without a decision and records the conditions in its `setting` event. When one fails, the ask opens the owner's decision as before and names it.
- `ask --kind crisis --crisis host|data|security|artifact` is the one class that reaches the owner unasked: it opens an owner decision and messages the owner. `status` and `inbox` end with `owner: nothing needed`, the open crisis, or what waits on the owner when convenient (JSON `owner`).
- docs/state.md#authority classifies every owner-required row as a one-time grant: configuration set once, or a one-use approval for one named case that an ordinary day does not reach.
