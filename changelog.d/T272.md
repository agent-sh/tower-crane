- The worktree lock moved from the repository's git directory to `tower-crane-worktree.lock` in the worktrees root. A sandboxed worker writes the git directory, so it could hold the old lock to stall gates, dispatch and prune for a minute, or delete a held one. No sandboxed agent writes the worktrees root.
- Upgrading: a process that holds the new lock also holds the old path while it is free, so an older Tower Crane process still running waits for it. A lock already at the old path is not waited for; each process that finds it prints a notice naming it. Stop older processes after upgrading, then remove it.
- Removing a task worktree (cancel, retirement, `worktree prune`) and each prune now run under the worktree lock, so a relink no longer writes into an admin directory git is emptying.
- An agent file with `sandbox: true` and `writeOutside: worktrees` is refused.
