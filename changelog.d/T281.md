- Security: a sandboxed claude or codex agent holds no GitHub credential. Spawn no longer hands it the user's gh token, the supervisor removes `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and `GITHUB_ENTERPRISE_TOKEN` from its environment whatever set them, and its rendered git config adds no credential helper. Before, every sandboxed agent got the user's own gh token, so `/usr/bin/git` or `curl` could push to any branch, change workflows or delete a repository.
- A sandboxed agent's `git push` of its task branch and its `gh` commands now go through its state broker, which runs them on the host with the user's login. A push names only a commit: the broker pushes it, without force, to the task branch on `origin`, which must be the project's recorded repository (or a local path when none is recorded), and refuses a push that changes a `.github/workflows/` file the task does not name. gh runs in the recorded repository with gh's flag table (`lib/gh-flags.json`), only on the task's own pull request for writes, without host-only flags such as `--web` or file paths, and in an environment of only what gh needs. `gh search` and `gh status` are not available to sandboxed agents, and brokered gh needs `project set --repo`.
- docs/state.md says what holds now, that unsandboxed agents (opencode, agy, pi, `command`) get no token guarantee, and the default-branch ruleset to keep on GitHub.
