- On Windows, a state read or write that meets a refusal lasting past the 2 s wait fails after that one wait, as `docs/state/storage.md` says. A refusal caught by the snapshot key, the schema check after a failed read, a staged commit's read, the log check, or a writer's preparation or locked snapshot started another 2 s wait from the next read, so the read waited a multiple of the bound before it failed, or went through once the scanner let go. The Windows state compatibility repeat hung when that happened: its supervisor never failed at the bound.
- A state broker answers a shim from before framed packs as soon as it sees the bare pack, before git runs. On Windows that shim's pipe closes 50 ms after it ends its side, which index-pack often outlasted, so the shim lost the answer.
