- Accepting or cancelling a task archives its scratch to `archive/<task>/` in the state directory before the scratch is removed. The manifest lists each file's path, size and SHA-256. Text gets the gate log redaction, files over 8 MiB keep their head and a truncation notice, and the archive stops at 64 MiB. Tool caches are left out. The walk follows no link and checks each directory and file where its opened descriptor lies, so a worker still running cannot swap a host directory into the archive. Archives are kept for `archive.retention_days` (default 30, operational).
- A scratch path cited by the PR body, the task's notes or evidence, or a decision is archived whole. Accept refuses and names a cited path that is missing, an empty directory, not a regular file or over 32 MiB. A glob, shell variable or `<placeholder>` cites nothing, and a `:line` or `#Lnn` location after a path is not part of it. Accept checks the gates before it reads the scratch, so an accept the gates refuse writes no archive.
- A refused accept shows in `inbox` as `archive_refused` with its paths, so an automatic accept that refuses is seen. The orchestrator sets aside a stale citation with `accept ID --drop-citation PATH --reason R` (operational `accept.drop_citation`, audited); the manifest keeps it under `dropped`. A drop counts only once an accept that names it lands.
- `tower-crane task archive ID` lists an archive. `--into T` copies files into T's scratch and records `archive` evidence on T. The orchestrator copies into any open task; T's worker copies only from an archive granted to T with `--grant T`.
