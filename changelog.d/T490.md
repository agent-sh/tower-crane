- Crucial mode: with `tests.crucial` (`project set --tests-crucial JSON`), expensive proof and a pinned map, the tests gate runs the crucial files, the changed tests and the mapped suites of the change, and no full suite. It needs no PR or hosted full-suite job. The merge queue's head check runs the same selection.
- A changed file no map entry covers is a coverage gap: the task's changed tests must run it under V8 coverage at head, or the gate fails with `coverage gap:`. A crucial path missing at head is a `tests_crucial` configuration failure.
- `tower-crane tests map refresh --from-run RUN_ID` pins `tests.map` from a run's `tests-coverage-map` artifact, keeping declared globs and paths coverage cannot measure. `scripts/tests-coverage-map.js` and `TC_TEST_COVERAGE_DIR` in `test/run.js` build that map from per-test-file V8 coverage, counting the CLI processes a test starts.
- CI: main pushes run only `checks (shared files)` on the pushed range. Fork PRs, daily, manual and `v*` tag runs run the full matrix with the proofs and repeats. Daily and manual runs also build the coverage map.
- Releases read the newest schedule or manual run of each workflow that has one: it must be green and at or after the base head. Workflows without full runs keep the push rule. The inbox keeps a red daily run red past newer green pushes.
