- Urgent tasks run on the hard rung. `task update --priority urgent` raises an easy or medium task to hard unless its tier was set with the new `--tier-reason R`, and setting an urgent task below hard needs that reason.
- A task without a tier range steps up one code rung after its second rework from its own work at one rung: a failed review, or a failed tests, clean or ci gate main does not share. Conflicts, stack syncs, manual reworks and main's own failures do not count. The next attempt goes to a new worker, not back to the PR owner.
- Each step is a `climb` event, listed in `status` (`climbed:`, JSON `climbs`) and `task show`. `task update --tier` overrides it, and `gates retry --from-rework` that undoes the counted rework puts the tier back.
