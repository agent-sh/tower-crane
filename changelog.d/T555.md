- Urgent tasks run on the hard rung. `task update --priority urgent` raises an easy or medium task to hard unless its tier was set with the new `--tier-reason R`, and setting an urgent task below hard needs that reason.
- A task without a tier range steps up one code rung after its second rework from its own work at one rung: a failed review with a finding beyond prose, a tests, clean or ci failure its gate confirmed, or a failed host probe. Conflicts, stack syncs, manual reworks, main's own failures and unconfirmed failures such as timeouts, killed runners and cancelled CI do not count. The next attempt goes to a new worker, not back to the PR owner.
- Each step is a `climb` event, listed in `status` (`climbed:`, JSON `climbs`) and `task show`. `task update --tier` overrides it, and `gates retry --from-rework` that undoes the counted rework puts the tier back.
