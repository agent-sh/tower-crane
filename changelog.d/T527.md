- A sandboxed claude agent's commands no longer get credential-shaped variables. claude starts with a `--settings` flag that sets `sandbox.credentials.envVars`, which unsets each such name in claude's launch environment for the commands its sandbox runs, whether it comes from the dispatcher's environment, `env`, `env_file` or the provider routing. The names stay out of `settings.json`. claude itself still gets them. Tower Crane's own variables and names that are not credential-shaped still reach the commands. On Linux, bubblewrap, which starts each command, still holds claude's environment. `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` stays unset: in Claude Code 2.1.305 it writes stub files into the worktree and makes `package.json`, lock files, `scripts/` and `.github/` there read-only to commands.
- A sandboxed claude agent that keeps the caller's temp directory now allows that directory back inside `/tmp` by the `TMPDIR` it starts with, after the project's `env` and `env_file`, not the dispatcher's. The notice spawn prints names that `TMPDIR` too.
