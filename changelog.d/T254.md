- State writes parse the event log and snapshot files before waiting for the lock. Under the lock they read only the events appended since and keep the parsed files unless one was replaced. Writes still fsync.
- Rendering the sketch runs outside the lock. The lock covers only the publish, and a sketch of later state (`sketch.stamp`) is never replaced by an older one.
- Orchestrator reads such as `status` take no lock. The lease heartbeat renews once it is a sixtieth of the lease window old, and a read tries the lock once instead of waiting.
- Lock waiters retry as soon as the lock is released instead of sleeping out their backoff.
- `TOWER_CRANE_LOCK_TRACE=FILE` records lock wait, hold and event bytes read per holding.
- Views index events by task, so status and the sketch no longer scan the whole log per task.
