- A worker spawn refuses a task that a live reservation holds, naming the holder. A reservation whose monitor and harness process group have both exited is recorded as cleared under the state lock before the first capacity check, so it no longer holds a worker slot. Exit is probed on Linux, macOS and Windows.
- A supervised worker's harness starts only after its supervisor takes the worker's lease, so no worktree write precedes the lease on POSIX. On Windows the harness still starts before its claim. A worker whose lease is refused or cannot be taken, or whose spawn is not recorded within 10 seconds, stops with `no lease` and exits non-zero. The agent's own claim renews that lease, and a worker's exit leaves its lease in place until it is released. `supervision.claim_ms` is removed; a rung that still sets it is refused as an unknown field.
- A supervisor stop stays blocked with its reason, and exits non-zero, whatever exit code its harness reports after the stop.
