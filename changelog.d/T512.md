- `gates.executors` counts CPU work on this host only: the tests gate with its host probes, the clean gate, local CI and the merge line's head check. Review dispatch, accept, hosted CI reads and the waits on GitHub or a reviewer take no executor and never wait for one. A reaction starts at once and takes an executor when it reaches CPU work. When every executor is busy it still reads CI, so a CI failure sends the task back before its suite runs, then waits in queue order for a free slot. `executor` events record the leases.
- Rechecks of pending CI read GitHub at most once per task per minute across every watcher; a first read at a head and a completion notification read at once. `ci poll` events record the reads.
- `status` prints `gate executors: N of CAP in use: TASK KIND`, `waiting on GitHub checks: TASKS` and `waiting on review: TASKS`; JSON has `gate_executors` and `waiting_on`. The inbox's `executors` lists CPU leases. `merge --accepted` and `gates retry --from-rework` wait for a free executor for their CPU work and say so once.
