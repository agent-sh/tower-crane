- `merge` retries through GitHub's asynchronous merge API when `gh pr merge` refuses a PR as part of a stack that no task records, instead of failing. The retry is the same squash (or merge): it sends the same subject and body and pins the accepted head with `expected_head_sha`, then records the merge commit GitHub writes. After the merge is confirmed it deletes the head branch unless `merge.keep_branch` is set, as the ordinary merge does. With `merge.admin` set it refuses, since the API has no admin option. A rebase keeps the refusal, since the API cannot rebase.
