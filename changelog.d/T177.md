- A failed `tests`, `clean` or `ci` gate at a submitted head no longer waits for an operator. A timeout, a runner killed by a signal, or a CI run or local CI command that timed out runs the gate once more at the same head. Any other failure, or a retry that fails too, sends the task to rework with the gate's summary: the failing test names and the output tail. A confirmed quality failure on a task with a tier range keeps its escalation climb.
- A change with no test, or with no changes against the base, reworks with the gate's reason. A missing or uninstalled pinned command is project configuration: the task stays submitted, and the inbox shows a `gate_config` item addressed to the orchestrator that names the setting. `gates retry` reruns the gate once the command is pinned.
- A test or cleanup command killed by a signal is recorded as `runner_crash`, not as a confirmed quality failure, so a crash no longer climbs a rung. A shell reports the signal as exit 128 plus its number, and that exit counts the same.
