- The local CI output tail test no longer loses or reorders its fixture's output on a busy runner. The fixture ended with `process.exit(1)`, which drops the stdout writes node still queues when the gate has not read its socket yet; that socket holds about 170 small writes. It now sets `process.exitCode`, so node drains its output first. Its failing step moved from stderr to stdout: the gate joins the two streams in arrival order, so a stderr line can land far from where it was written. The gate code was right.
