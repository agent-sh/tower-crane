- Sandboxed claude and codex agents read nothing under the user's home but the paths they need: the worktree and its git directories, their writable directories, their own home and broker directory, the state directory, the Tower Crane checkout, the node installs and harness programs they run, the files their git config names, the user's rule files and the new owner-required `sandbox.read`. T106's credential table is gone: `~/.config/gh`, harness logins, `~/.aws`, `~/.docker/config.json`, `~/.npmrc`, `~/.netrc`, OpenCode's `auth.json`, env-pointed files under the home and any tool's dotfile are hidden without an entry. claude denies the home and reopens the list, and a `PreToolUse` hook (`lib/read-guard.js`) applies the same list to Read, Grep and Glob. codex hides each home entry that holds no listed path, since it cannot reopen a readable path under a hidden one; an entry created after spawn in a split directory stays readable until the next spawn. Credential files outside the home are no longer hidden.
- A sandboxed agent's git config is rendered from the user's global config with includes flattened and no credential helpers or auth headers; its one helper gives GitHub the handed `GH_TOKEN`. A repository rule under the home outside the readable paths refuses startup, and a `sandbox.read` path that is the whole home refuses dispatch.
