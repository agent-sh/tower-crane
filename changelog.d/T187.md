- Sandboxed claude and codex agents read nothing under the user's home but the paths they need: the worktree and its git directories, their writable directories, their own home and broker directory, the state directory, the Tower Crane checkout, the directories and global package directories of the node binaries they run, the harness programs on `PATH`, the files their git config names, the user's rule files and the new owner-required `sandbox.read`. This replaces the credential-store denylist and its discovery of env-pointed, profile-named and dotenv-assigned paths: `~/.config/gh`, harness logins, `~/.aws`, `~/.docker/config.json`, `~/.npmrc`, `~/.netrc`, OpenCode's `auth.json`, env-pointed files under the home and any tool's dotfile are hidden without an entry. claude denies the home and reopens the list. A `PreToolUse` hook (`lib/read-guard.js`) applies the same list to Read, Grep and Glob. codex reads nothing through `:root`: its profile names `:minimal`, each entry of `/` outside the home and the list, so the rest of the home is never mounted and the profile stays a few kilobytes however large the home is. Credential files outside the home are no longer hidden.
- A sandboxed agent's git config is rendered from the user's global config with includes flattened and no credential helpers, auth headers, mail password or URL userinfo; its one helper gives GitHub the handed `GH_TOKEN`. A repository rule under the home outside the readable paths refuses startup, and a `sandbox.read` path that is the whole home refuses dispatch.
- A change may correct an existing changelog fragment that it made untrue; `npm run check:shared` still refuses edits to `CHANGELOG.md` and deleted fragments.
