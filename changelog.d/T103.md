- Git the CLI and gates start, directly, through `gh` or through the pinned cleanup tool, no longer runs commands from repository config or hooks a sandboxed worker can write. Only hooks from the user's own absolute or `~/` `core.hooksPath` run, fsmonitor and auto-maintenance (which runs `gc.recentObjectsHook`) are off, and `core.sshCommand`, credential helpers, external diff, filter, diff and merge drivers, signing programs and `gpg.ssh.defaultKeyCommand`, aliases (which a remote helper URL can run), pagers, and origin's pack commands come from the system, global or command scope only (docs/state.md#worker-written-code-and-config-outside-the-sandbox). Repository `protocol.*.allow` keys cannot reopen a protocol, and `GIT_PROTOCOL_FROM_USER=0` refuses a remote helper beyond `http`, `https`, `git`, `ssh` and `file` unless the user's own config allows it. The caller's `GIT_SSH`, `GIT_SSH_COMMAND`, `SSH_ASKPASS` and `PAGER` still apply. The same section says the tests and clean gates run worker-authored code outside any sandbox and which environment they get.
- Repository config files included through `include.path` or `includeIf`, whatever the condition, are covered, so a `gitdir:` or `onbranch:` include that matches only in a task or gate worktree cannot add a driver. Repository Git proxies are neutralized through `GIT_PROXY_COMMAND`. Git or gh is refused when the config scan fails or exceeds its output buffer.
- Git calls that read no object, index or hook (`rev-parse` locating the repository, `worktree list`, `prune`, `lock` and `unlock`, `remote get-url`) skip the scan, and a process reuses a scan while the files it read are unchanged, so a run of git calls in one checkout scans once per caller environment instead of once per call. A config file with no include is read from the scan's own listing rather than parsed by a git process of its own.
- The generated-file repair pushes to `origin` by name after checking its push URL in the worktree it pushes from, so a repository `url.<base>.pushInsteadOf` can no longer send the push to a local repository whose hooks would run. Pushes `gh stack sync` makes still go to the origin URL the repository config names.
