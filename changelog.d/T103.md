- Git the CLI and gates start, directly, through `gh` or through the pinned cleanup tool, no longer runs commands from repository config or hooks a sandboxed worker can write. Only hooks from the user's own absolute or `~/` `core.hooksPath` run, fsmonitor is off, and `core.sshCommand`, credential helpers, external diff, filter, diff and merge drivers, signing programs and `gpg.ssh.defaultKeyCommand`, and origin's pack commands come from the system, global or command scope only (docs/state.md#worker-written-code-and-config-outside-the-sandbox). The caller's `GIT_SSH` and `SSH_ASKPASS` still apply. The same section says the tests and clean gates run worker-authored code outside any sandbox and which environment they get.
- Repository config files included through `include.path` or `includeIf`, whatever the condition, are covered, so a `gitdir:` or `onbranch:` include that matches only in a task or gate worktree cannot add a driver. Repository Git proxies are neutralized through `GIT_PROXY_COMMAND`. Git or gh is refused when the config scan fails or exceeds its output buffer.
- Git calls that read no object, index or hook (`rev-parse` locating the repository, `worktree list`, `prune`, `lock` and `unlock`, `remote get-url`) skip the scan, which cuts the scans on the spawn path from 116 to 18.
