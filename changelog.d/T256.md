- Git and gh that Tower Crane starts refuse to run while the repository's common directory holds a `commondir` file, or while a worktree admin directory names a common directory that does not hold it. A sandboxed worker can write either, and git then reads another repository's config, hooks, refs and objects, and Tower Crane that repository's state. The message names the file to remove or restore.
- Where git's answer decides a path (the state directory, a spawn's git directories, the gates' worktree lock), it must match the location Tower Crane finds from the files, so a `commondir` that appears between the check and git's lookup is refused instead of redirecting the state.
- The supervisor watches the common directory, removes a `commondir` file as soon as it appears and checks again when the agent exits. It records at most one `commondir removed` event per sample interval, with a count. The owner's own git that runs while the file exists is not covered (docs/ladder.md#the-common-directorys-commondir).
- Git that Tower Crane starts runs with `GIT_NO_REPLACE_OBJECTS=1`, so replace refs a worker writes do not change the history it sees.
- A spawn refuses a task worktree whose `.git` file names a git directory other than one of the repository's worktree admin directories, instead of granting that directory to the sandbox.
