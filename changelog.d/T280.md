- Security: a sandboxed codex agent now runs its `git` and `gh` shims. Its sandbox hid them with the rest of `homes/<agent>/`, since codex cannot reopen a readable path inside a hidden one, so `git` and `gh` were the host's and the push and gh policy never applied to codex agents. The shims, their policy, a copy of `lib/` and a `package.json` that keeps them CommonJS now sit in `home/.tower-crane-shims/`, which the sandbox binds read-only inside the agent's writable `HOME`. A project or `HOME` `package.json` with `"type": "module"` does not break them. A push or PR a codex agent makes through them is not recorded as a hook event.
- docs/state.md says what the shims guard: they hold an agent that runs `git` and `gh` by name, not one that runs `/usr/bin/git`; what holds that agent is that it has no GitHub credential (T281).
- Every git and gh shim clears `NODE_OPTIONS`, `NODE_PATH`, `NODE_REPL_EXTERNAL_MODULE`, `NODE_PRESERVE_SYMLINKS`, `NODE_PRESERVE_SYMLINKS_MAIN` and `NODE_COMPILE_CACHE` before node starts. `NODE_OPTIONS=--require=FILE git` ran FILE in the shim. git and gh run without them too.
