- Security: a sandboxed codex agent now runs its `git` and `gh` shims. Its sandbox hid them with the rest of `homes/<agent>/`, since codex cannot reopen a readable path inside a hidden one, so `git` and `gh` were the host's and the push and gh policy never applied to codex agents. The shims, their policy and a copy of `lib/` now sit in `home/.tower-crane-shims/`, which the sandbox binds read-only inside the agent's writable `HOME`. A push or PR a codex agent makes through them is not recorded as a hook event.
- docs/state.md says what the shims guard: an agent that runs `/usr/bin/git` or uses `GH_TOKEN` directly is held only by the token and the repository's rules, and the token every sandboxed agent gets is the spawning user's own gh token.
