- A local CI run keeps its full stdout and stderr in `logs/ci-<task>-<sha>-<unique>/output.log` under the state directory, terminal escapes (CSI, OSC and other ESC sequences) removed and redacted, and records the path in `local_ci.log` on its evidence. A failed run also records `local_ci.output_tail`, the last 200 lines and at most 16384 characters, and its summary names the full log. Before, only the last 20 lines of stderr or stdout survived, and ginza's failing step was not among them. The newest 5 runs per task are kept.
- `ci.local.artifacts` (globs in the gate worktree) and `ci.local.artifact_pattern` (a regular expression for paths the command prints, such as `^Local check receipt: (.+)$`) name files that a failed `check ci` copies out of the gate worktree and its scratch before removal. They go to `ci-artifacts/` in the state directory, which every agent sandbox hides, with text files redacted. Evidence lists them in `local_ci.artifacts`; the summary only counts them. At most 100 files and 64 MiB per run, each read from one descriptor without following a final symbolic link.
- Gate worktrees and scratch now default to `tc/g` under the user's cache directory instead of the OS temporary directory, which is often a RAM-backed tmpfs. ginza's local CI failed under `/tmp` because its SSD campaign guard refuses dry media under `/tmp` or on tmpfs. The default keeps the gate `TMPDIR` within 62 bytes, the most full Chromium accepts, and falls back to the account's own cache, then the OS temporary directory. `gates.tmp_root` and `TOWER_CRANE_TMP` still override it, and `status` names the default's source `cache`.
- Each gate directory records its owner in `owner.json`, and a gate removes directories in its root whose owner on this host is gone and which are older than the project's longest command budget.
