- Merge and cancel remove the task's worktree once the state change is recorded. A worktree with uncommitted changes stays, and so does every worktree while `merge.keep_branch` is set, while git still has it locked, while a link in its path leads outside the worktrees root, or while a worker or reviewer for the task still runs in it. While git removes a worktree, claim, rework and spawn refuse its task, so a task sent back or claimed before the removal keeps the worktree. A `worktree kept` event says why, `worktree removed` records each removal, and git prunes stale registrations after each merge or cancel.
