- `status`, `inbox` and the orchestrator's observer (`wait --observe`, `--inbox`) read the task rows, the events of the tasks they look at and the few commands they list, through indexes. None of them reads the whole event log. On a copy of the live state (446 tasks, 77k events), `status` p50 went from 1099 ms to 221 ms and its CPU per run from 1640 ms to 300 ms; `inbox` p50 went from 1117 ms to 264 ms. `docs/state/storage.md#view-latency` has the p95 and the host load.
- The gate queue reads its reaction receipts, queue entries, requests and acceptances through indexes, the CPU executor count reads only the leases still running, and the merge queue reads its newest entries first. A repeated `merge` of a merged task checks its receipt against that task's own events. Drain order and the queue that `status` and `inbox` show are unchanged.
- `state.db` has four more indexes: `(cmd, task, pos)`, the agent an event's detail names, and the source and phase of reaction receipts. The first command that can write a database built before them adds them; until then reads return the same rows, more slowly.
