- The host governor grants test threads. Every test run inside Tower Crane, from a gate, a worker or a reviewer, takes a lease from one host-wide budget: the cores but one, less what other work uses now; past the CPU pressure or load defer lines it stops growing and steps down by the overshoot, at most every 30 seconds and never below one thread per run. A run asks for its `--test-concurrency` and gets at most that, at least one thread. The lease ends when the run exits or dies.
- `test/run.js` runs each test file in a runner of its own through a pool that follows the grant: it rechecks every 3 s, starts no new file while over a lower grant and starts more when the grant rises, logging each change once. Each file's output comes whole, and the run's totals and failures come again at the end. Plain `npm test` and CI keep their request.
- A sandboxed agent's test runs get their lease through the state broker, held by the spawn monitor while the run's connection is open: one lease per agent at a time, at most one registry refresh per recheck interval, and no line longer than a request.
- `status` shows the test-thread budget, every run holding threads on the host and its grant, and `status --json` has them under `governor.tests`.
