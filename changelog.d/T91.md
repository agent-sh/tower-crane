- The board's Controls view (`/controls`) reaches every authority setting through the existing CLI handlers, authority check and audit event: owner approvals, project limits and policies, pause, budgets, every rung field, personal fallbacks, the browser kit, task settings, release, interrupt, gate priority, waivers, decision delegation and orchestrator delegation. An owner-required change there opens the shared escalation; approving it applies the recorded request once. Publish approvals, and requests with flags the board does not send such as `spawn --wait`, are approved and left for the orchestrator's repeat. Releasing another agent's live claim from the board opens the owner's decision. A save beside unsaved input reloads the data the selectors fill from, so a later save cannot revert it. `project set --paused REASON` blocks new claims and dispatches; `''` resumes. `GET /api/controls` serves the same data as JSON.
