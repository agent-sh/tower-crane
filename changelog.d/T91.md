- The board's Controls view (`/controls`) reaches every authority setting through the existing CLI handlers, authority check and audit event: owner approvals, project limits and policies, pause, budgets, every rung field, personal fallbacks, the browser kit, task settings, release, interrupt, gate priority, waivers, decision delegation and orchestrator delegation. An owner-required change there opens the shared escalation; approving it applies the recorded request once. Approving an orchestrator's escalation, or a publish request, records the answer for the orchestrator's repeat of the same command, which makes the change once. The owner's own request reads as a change to confirm, not one the orchestrator makes. Releasing another agent's live claim from the board opens the owner's decision. A save beside unsaved input reloads the data the selectors fill from, so a later save cannot revert it. `project set --paused REASON` blocks new claims and dispatches; `''` resumes. `GET /api/controls` serves the same data as JSON.
