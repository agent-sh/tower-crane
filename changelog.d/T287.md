- A broker start removes the `/tmp/tower-crane-XXXXXX` socket directories that spawn monitors killed before closing left behind. A broker's `/tmp` directory now holds an `owner.json` record with the monitor's pid, host and start time. A directory goes only when it is this user's, older than a minute, and its owner on this host has exited or its pid names a later process. A live owner keeps it even when its socket refuses connections. A directory from an older version, with no record, goes when it holds only a socket that refuses connections.
- A start that cannot listen removes the `/tmp` directory and broker directory it made. A start refused before it listens removes the broker directory too. A failed cleanup no longer hides the error that caused it.
- Something an agent leaves at `broker.sock` in its temp directory no longer fails every later spawn with `Path is a directory`, and no longer stops the broker's close before it removes the broker directory. The broker never walks a tree the agent wrote: it removes an empty directory, renames a full one aside as `broker.sock.stale-<random>`, and unlinks a file or link without following it.
- Closing a broker no longer deletes its broker directory recursively. A codex agent writes that directory, and a link it swapped in during the walk could lead the delete outside. The broker removes only the entries it wrote, without following links, then the empty directory. A directory with anything else in it is renamed aside to `brokers/.stale-<agent>-<random>` with a notice. The broker's `/tmp` directory goes the same way.
- A spawn removes a dead agent's home and broker directory only once its monitor, its harness and every process left in the harness's process group have exited. Before, a process the agent left behind could still write the tree while it was deleted. A spawn also removes `brokers/.stale-<agent>-<random>` directories once their agent is gone.
