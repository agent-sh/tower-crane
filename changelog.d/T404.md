and memory caps. Linux systemd scopes retain nested work in delegated child
cgroups. Other hosts use a process/RSS watchdog. Operational `--tasks-max` and
`--memory-max-bytes` settings control the caps; defaults use host and ancestor
slice limits. Cap failures name the resource in blocked spawns and gate output.
  Fixture CLIs preserve shells, hooks and explicit owner scope wrappers; containment probes
  explicitly exercise enforcement. Unsupported delegation uses the watchdog
  within the existing parent fence.
  Agents omit dispatcher fixture preloads and retain explicitly configured preloads.
  Systemd scopes use `OOMPolicy=kill` to stop the whole attempt on an OOM.
  Optional scope properties cannot override the caller's slice or mandatory caps.
  Configured outer scopes fail when the user manager is unavailable.
  Linux task defaults use the effective PID/thread budget without a fixed 256-task
  clamp; scope metadata retains task/memory peaks and refused forks.
  Gate defaults divide the reserved host budget by executor concurrency to leave
  suite headroom. Unspecified resource fields remain computed at launch; explicit
  caps apply unchanged to agents and gates. Linux unlimited PID budgets use
  kernel thread and PID ceilings.
  Normal agent exit preserves independent dispatch and wait controllers inside
  their existing bounds. A detached engine keeper maintains the retained
  watchdog and scope until that work ends; ordinary strays and gate-owned
  descendants still stop on cleanup.
