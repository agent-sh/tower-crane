- A hotfix reaction's tests and clean gates, which `accept` runs, take the reaction's executor again: a full cap queues the reaction instead of running its suite beside the others. Since accept runs tests, clean and CI in order, a queued hotfix reads no CI until a slot frees. The automatic accept of an ordinary task uses the same lease for any gate it runs, and the lease is released before its CI read and review dispatch.
- A tests gate in mode `none` takes an executor when the task declares host probes, since the gate still runs them on this host. The final review never takes one.
