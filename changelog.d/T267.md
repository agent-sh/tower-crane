- State lives in one SQLite database, `state.db` in the state directory, opened by each command through `node:sqlite` in WAL mode with `synchronous=FULL`. The project, the decisions and the tasks file's envelope are documents, each task is a row, each event is a row, and an inbox table indexes the messages no hook has delivered yet. A commit is one synced transaction, so a killed process leaves all of it or none of it.
- The first command on a state directory in the file layout of 0.1 migrates it under the state lock, after recovering any interrupted 0.1 commit. `project.json` becomes a schema 2 marker, which every tool through 0.1.3 refuses before it reads or writes state, and the old files move to `legacy/<time>/`.
- Event cursors keep counting bytes as `events.jsonl` did, so `OFFSET:CUTS` cursors, hook bindings and `GET /api/messages?after=` from before the migration still name the same place.
- `tower-crane state export DIR` writes the file layout back for a 0.1 tool, with the migrated log byte for byte and every later event at its cursor.
- Writers read the state before the lock and, under it, only what was committed since; long-lived readers catch up the same way.
