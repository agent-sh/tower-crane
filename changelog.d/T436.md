- `TOWER_CRANE_INTERVALS` replaces the state lock wait and marker refresh, the supervisor startup windows and the governor's registry waits with a JSON object of milliseconds, so tests run timeout paths in short real time. Production leaves it unset; an unknown name or a non-positive value fails the command.
- `test/run.js` caps file workers at one below the core count instead of 4; `npm test` still asks for 4, and a caller on a large host, such as the tests gate, can ask for more.
- `test/run.js` starts files in about longest-first order. `node --test` sorts the paths it gets as text, so the runner spells the longest files, one worker's worth to a band, with more `../` steps up from the working directory, then as absolute paths; each band sorts before the next, and the shortest files keep plain paths.
- `test/isolation.test.js`, whose tests in turn ran about as long as the whole 12-worker host run (610.7 s), is three files; the merge-queue tests of `test/automation-dispatch.test.js`, the merge and executor tests of `test/automation-gates.test.js` and the merge races of `test/events.test.js` have files of their own. `test/durations.json` is measured again from six main runs.
- The governor's starting reservation for a tests gate and a merge-queue suite is 2560 MiB, up from 2048: Tower Crane's own suite at 12 file workers peaked at about 2.5 GiB.
- `scripts/suite-profile.js` profiles a suite run: wall time and CPU per test and per file, the share spent waiting, and the host's load and the run's peak memory. `--max-wall SEC` fails a run that took that long, so a tests gate host probe can hold the suite to a time.
- `scripts/mutants.js --deadline-floor MS` lowers the 30-second floor of a mutant's deadline.
- Test waits that run a CLI check pause as long as the last check took, instead of rerunning on that CLI's own lock files. Timer-bound tests use short intervals: the state-lock timeout test now holds the lock past a short lock wait and proves the retry's write timed out, which it did not do under the 60 s production wait. Each interval keeps one test at its production value on the real clock.
