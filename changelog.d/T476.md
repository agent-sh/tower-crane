- Local CI runs on a pinned merged tree: the base read at the start stays the receipt's `base_sha`, a base that moves during the run no longer voids it, and the receipt stays valid for acceptance and task reports while the base still contains that commit. A rewritten base invalidates it. Merge still requires the receipt's base to be the base it lands on, and the merge queue reruns local CI on the fetched base.
- An infrastructure void never reworks a task. A gate interrupted by wait shutdown records `voided: true` and reruns without using up its retry. A `gates retry --from-rework` whose rerun is stopped before a verdict (a governor stop, missing engine code) keeps the task submitted at the restored revision with its other gates, and the next reaction reruns only that gate; the `restore` event records `rerun`.
