- Lock recovery records each cut it makes to `events.jsonl` in `events.cuts.jsonl`. Tailing readers (`wait`, `serve`, the wait host's history) go back to a recorded cut instead of resuming mid-line, so no event appended after it is skipped, even when the log grew past where they stopped. `wait --after OFFSET` and `GET /api/messages?after=OFFSET` read a cursor inside a recorded cut from where the cut left the log.
- Sketch stamps compare the cut count before the log size, so a render that stamped torn bytes no longer keeps later writes' sketches out.
- A recovery that Windows stops because another process holds a staged commit file open counts as a busy lock: writers retry until their deadline and exit 3, and try-locks exit 3 at once.
- Lock holders delete temp files that dead writers left in the state directory.
- Recovery refuses, without touching them, staged commits under a newer `schema_version`.
- A write or the wait host keeps parsed state files only for the event log it read them with, so a file that reuses a replaced one's inode, size and times can no longer show state behind the events.
- docs/state.md says that macOS file syncs use `F_FULLFSYNC` and which released versions share the commit protocol.
