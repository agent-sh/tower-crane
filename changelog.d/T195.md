- Sandboxed claude and codex agents can no longer write the shared git directory's `config`, `config.worktree`, `hooks/`, `info/`, `remotes/`, `branches/`, `worktrees/`, submodule configs and hooks, or their worktree's `commondir`, `gitdir`, `config.worktree` and `.git` file; commit, rebase, fetch and push still work. A task worktree's admin directory now lives in `.git-admin/<name>` under the worktrees root, reached through a link in the git directory's `worktrees/`, so no agent can write another worktree's admin directory, including one added after it started. Those paths are relative, and Tower Crane rewrites git's back-pointer before each prune, so moving the project directory keeps the worktrees; it relinks only its own repository's worktrees, under the same lock as worktree creation and gate preparation. For claude these carve-outs cover every sandboxed role in a linked worktree, since claude grants the git directory to all of them. Spawn starts their harness with a git environment that runs no repository-supplied command (`core.fsmonitor`, hooks, drivers, no system config, no background gc) and the rendered global git config at `gitconfig/<agent>` in the state directory, which the agent cannot rewrite; harness status and diff ignore gitlink contents so nested repository drivers cannot run; the agent's own sandboxed git keeps the repository's hooks. `tower-crane worktree` makes the task branch track its namesake on origin, so a plain `git push` publishes it.
