- Engine helpers pass the automation key on the first line of their CLI child's stdin, named by `TOWER_CRANE_AUTOMATION_KEY_FD`, instead of `TOWER_CRANE_AUTOMATION_KEY` in its environment. The orchestrator's Stop hold runs `wait --inbox` for as long as it idles, and Linux kept the key readable in that process's `/proc/<pid>/environ` the whole time.
- A home build writes `automation.key` to a staged file and renames it into place, so a helper reading the key during a rebuild no longer finds it empty or half written.
- The CLI ignores `TOWER_CRANE_AUTOMATION_KEY_FD` when that descriptor is a terminal, so a marker leaked into an interactive shell never waits for input. A key line longer than 256 bytes is refused with exit 1.
