- Sandboxed claude and codex agents cannot read the user's credential stores: gh, claude, codex, docker, npm, pypi, cargo, netrc, git-credentials, kube, gcloud, azure, ssh and aws, through Bash (claude's sandbox) and claude's Read, Grep and Glob tools (Read deny rules). Before, claude hid only `~/.ssh` and `~/.aws` and codex hid none, so a worker could read the gh login, the model credentials and registry tokens and send them anywhere. A store holding the agent's house rules, such as `~/.codex/AGENTS.md`, hides its other entries. Sandboxed homes no longer link `.config/gh`; gh uses the handed `GH_TOKEN` and its own config directory even when the user sets `GH_CONFIG_DIR` or `XDG_CONFIG_HOME`.
- Denials follow credential-location overrides, including every `KUBECONFIG` entry, and cover Tower Crane config and Pi/Agy credential files. Repository rule imports cannot create read exemptions; imports resolving to protected credentials refuse startup before the harness runs.
- Symlinked credential targets are protected even outside a store. Environment overlays retain the original, project, route and selected env-file locations in the deny list. The supervisor enforces gh's isolated config after settings on initial, retry and fallback launches.
- Credential discovery includes Claude settings, Codex dotenv assignments and resolved provider launch paths, so custom AWS files remain hidden when the harness supplies their locations.
- Relative credential paths remain denied under both the caller and worker directories across route fallbacks. Google application-credential and Cloud SDK credential-file overrides are included across all discovered environment sources.
- AWS web-identity token files are denied across all discovered environment sources. Credential stores that equal a required rule or runtime path refuse dispatch, including symlink aliases, instead of exposing the whole store.
- AWS profile `web_identity_token_file` paths are denied from default and overridden config/credentials files, across profiles and environment layers. Nested credential links to required runtime paths refuse dispatch before exemptions can expose their targets.
- Denials include AWS container authorization tokens, Azure federated tokens and client certificates, and Claude mTLS client keys across all collected environments. AWS profile token paths strip whitespace-prefixed inline comments to match the provider's INI parser.
- OpenCode's `auth.json` and `mcp-auth.json` are denied at their default data location and under every collected `XDG_DATA_HOME`, including relative paths and aliases. Credential locations with `~/` retain literal and home-expanded interpretations. Repository imports of these files refuse startup.
- A relative `CLAUDE_CONFIG_DIR`, `CODEX_HOME` or `PI_CODING_AGENT_DIR` resolves from the caller's directory on route fallbacks too. Before, the fallback resolved it from the worktree and dropped the caller's credentials, and the paths their `settings.json` and `.env` select, from the deny list.
- Every launch denies the credential paths selected by every configured `env_file`: the project's, the rung's and each fallback route's. Before, only the launching route's file was read, so the primary left the fallback's stores readable and a fallback left the primary's.
