- Sandboxed claude and codex agents cannot read the user's gh login. Sandboxed homes no longer link `.config/gh`; gh uses the handed `GH_TOKEN` and its own config directory even when the user sets `GH_CONFIG_DIR` or `XDG_CONFIG_HOME`. The supervisor enforces gh's isolated config after settings on initial, retry and fallback launches. Before, a worker could read the gh login and send it anywhere.
- Repository rules and their imports open no read paths in the sandbox; a repository rule the agent may not read refuses startup before the harness runs.
- A relative `CLAUDE_CONFIG_DIR`, `CODEX_HOME` or `PI_CODING_AGENT_DIR` resolves from the caller's directory on route fallbacks too. Before, the fallback resolved it from the worktree and lost the caller's harness directory.
