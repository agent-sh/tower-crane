- A nested attempt's OOM no longer stops its parent scope on systemd 255: scopes use `OOMPolicy=continue`, the runner sets `memory.oom.group=1`, and the supervisor and keeper read the scope's own OOM from `memory.events.local`, every millisecond while the scope is at its memory cap.
- On Windows, containment waits for a slow CIM process snapshot and stop as long as other Tower Crane snapshots do, instead of failing the attempt with `resource-monitor-failed` after 2 seconds; a contained command that exits before its first snapshot still has the children it started found, stopped or retained; a gate command's leftovers are stopped from a final snapshot; and the attempt's containment finishes only after its stop does.
- A caller outside its systemd user manager, such as a hosted CI runner's service, gets its scope in the manager's slice of the same name; the containment tests assert that placement there.
- A process that outlives its test no longer recreates the test's removed fake host when it records on the governor registry.
- Windows CI: automation test agents reach the offline GitHub through an explicit preload again, the merge-queue race test runs as two tests of five rounds, the lifecycle fixtures leave room for CIM snapshots, and `test/durations.json` is measured again so the three shards balance.
- CI shards print a line as each test file starts and ends, and a shard still running 40 minutes in, five under the test job limit, prints its live process tree, stops it and fails, so a hang leaves a log instead of a cancelled job. `TC_TEST_SHARD_DEADLINE_MIN` overrides the deadline.
- On Windows, the mutation runner's process snapshot and its cleanup of a mutant's descendants wait 30 seconds instead of 5, since each pass makes a CIM snapshot and a taskkill per member.
- The gate scratch proof reports the tests gate's base rerun cache, which stays in the gate root by design, apart from the scratch it must find removed. Test helpers no longer recreate a removed fixture's `detached` directory from a late monitor exit, and the shard deadline test keeps its nested run's seed inside its own fixture.
- The light PR-body check tests wait for a replacement reviewer instead of expecting it after a fixed number of passes, which a hosted Windows runner or a loaded host can need more of.
- A containment keeper runs from the tool's own directory, so on Windows it no longer keeps a worktree or test fixture it was started from from being removed.
